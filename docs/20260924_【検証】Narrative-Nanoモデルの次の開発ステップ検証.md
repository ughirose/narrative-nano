#### 1. budoux_chunks: 1 となった技術的要因の検証
BudouXの決定木モデルの内部構造を精査すると、前回作成した軽量スクリプトにおいて以下の2点の乖離が生じていた可能性が高いと考えられます。
- 文字種特徴量（Char Type）の欠落: BudouXは、文字そのもの（UW/BW/TW）だけでなく、漢字・ひらがな・カタカナ・句読点などの文字種境界（例: 漢字からひらがなへの遷移）を表す特徴量群（UB, BB, TB など）をスコアリングの主たる根拠としています。これらが生成されていない場合、マッチする重みの総量が閾値に届かず、境界判定スコアが常にマイナスとなって分割が一切発生しない状態に陥ります。
- TOTAL_PENALTY（閾値）の計算仕様: モデル辞書内に "TOTAL_PENALTY" という固定キーは存在せず、BudouX公式の実装では「モデル内の全重みの合計値の半分（sum(weights) / 2）」を実行時に算出して初期ペナルティ（閾値）として設定しています。これが 0 として扱われた場合、スコア判定ロジック全体が不整合を起こします。
- デコーダの自己除外ガード: チャンク数が1つの場合、デコーダ内の if (aIdx === pChunkIdx) continue;（述語自身を項の候補から除外するルール）によって唯一のチャンクがスキップされるため、引数候補が0件となり events: [] が出力されたと推測されます。
